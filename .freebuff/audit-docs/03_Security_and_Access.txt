1. Security posture
[TABLE]
PRIMARY PRINCIPLE
SamudraTrace AI handles potentially sensitive investigation evidence. Version one is local-first, least-privilege and human-reviewed. It ranks evidence-consistent candidates; it never declares guilt.

2. Deployment and trust boundaries
The MVP runs on a team-controlled laptop. The browser is untrusted input. FastAPI validates every request and owns access to models, files, database and scientific tools. FreeBuff/Next.js is a presentation client only. External data downloads happen during preparation and are cached before judging.

5. Object-level and row-level access rules
A user may read a case only when they own it, are explicitly assigned, or hold reviewer/admin scope.
Child records inherit access from their parent case; direct public access to artifact paths is forbidden.
Analysts may update only draft cases; approved evidence is immutable and requires a new revision.
Audit events are append-only. Users can read events for accessible cases but cannot edit or delete them.
Administrative service credentials stay server-side and are never prefixed NEXT_PUBLIC_.
If Supabase is adopted later, every table enables RLS and policies use authenticated user ID plus case membership—not client-supplied owner IDs.
6. Upload and geospatial processing controls
[TABLE]
Threat
Required control
Path traversal
Ignore supplied paths; generate server-side names; resolve and verify under artifact root.
Oversized or decompression-bomb file
Streaming size limit, raster dimension limit, band limit, time/memory budget.
Malformed GeoTIFF/NetCDF/CSV
Parse in isolated worker; validate magic/type, CRS, ranges, columns and timestamps.
CSV formula injection
Escape cells beginning =, +, - or @ in downloadable CSV.
Unsafe archive
Do not accept archives in MVP; if added, reject links and traversal entries.
Dependency/library exploit
Pinned lockfiles, vulnerability review and least-privilege process account.
Denial of service
Job queue limits, one heavy task per case, cancellation and timeouts.

7. API security requirements
Validate request and response schemas with Pydantic; reject unknown fields on sensitive endpoints.
Use explicit CORS origins and methods. Never use credentialed wildcard CORS.
Use secure, HttpOnly, SameSite cookies for browser sessions; rotate on login and privilege change.
Protect state-changing browser requests against CSRF.
Rate-limit login, upload, job creation and report generation endpoints.
Return opaque job and case identifiers; do not expose operating-system paths.
Set security headers: CSP, frame-ancestors, nosniff, referrer policy and permissions policy.
Document API versioning and reject unsupported clients clearly.
8. Evidence integrity and privacy
Calculate SHA-256 for every original and derived artifact.
Record model, preprocessing, environmental source, parameters, random seed and software commit.
Use append-only audit events with actor, action, timestamp and previous/current artifact hash.
Keep raw AIS and vessel data out of frontend logs, analytics and error traces.
Redact secrets, filesystem paths and stack traces from user-visible errors.
Require explicit reviewer approval before an evidence export is marked final.
Include a visible disclaimer: candidate ranking is investigative prioritization, not proof or legal attribution.

Vessel data is incomplete; confidence is reduced.
Continue cautiously; surface flags; forbid high-confidence label.

Cancel worker; mark job failed; permit retry.

Base map is unavailable; evidence layers still work.

10. Edge-case catalogue
Empty form, whitespace-only name or invalid observation time.
Duplicate case submission caused by double-click or network retry.
GeoTIFF has correct extension but invalid binary format.
Raster CRS is geographic while area calculation requires projected units.
SAR acquisition time falls outside environmental/AIS coverage.
AIS records are unsorted, duplicated, out of range or jump impossibly.
Same MMSI contains a large gap and must become separate track segments.
No vessel intersects the source corridor; system returns no credible candidate.
All candidate scores are close; system displays ambiguity rather than a forced winner.
Browser refreshes during a long job; job remains recoverable by ID.
Disk becomes low; new work stops safely without corrupting existing artifacts.
An approved case is edited; system creates a new revision rather than altering evidence silently.

12. Incident response
Contain: stop affected worker/API and preserve logs and hashes.
Assess: identify impacted cases, accounts, data and time window.
Recover: restore from immutable inputs, rotate credentials and rebuild derived artifacts.
Communicate: provide factual scope and limitations; do not speculate.
Learn: add a regression test and update threat model and runbook.
